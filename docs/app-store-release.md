# cark Android 应用商店发布清单

## 当前已具备

- Android 原生工程，包名 `app.cark.reader`，最低 Android 7.0（API 24），目标 API 36。
- 完整离线书架：导入、阅读、搜索、收藏、标签、阅读状态、批注和阅读位置。
- `.carkpaper` 文件选择导入，以及从文件管理器、网盘或系统分享直接交给 cark 导入。
- 文献包格式、论文身份、解压体积和资源 SHA-256 校验。
- 单篇删除、全部本机文献清理、存储占用估算和断开个人电脑连接。
- 禁止明文 HTTP、关闭 Android 备份、应用私有缓存、无存储权限。
- Debug APK 和 Release AAB 构建入口。
- 应用内隐私摘要与仓库隐私政策。

## 发布者必须完成

以下项目涉及发布者身份或不可提交的密钥，无法在仓库中代办：

1. 确定最终应用名、运营主体、支持邮箱和官网。
2. 确认包名 `app.cark.reader` 尚未被占用；一旦首次上架，不再更换。
3. 创建并离线保管 Android 上传密钥，不把 keystore、密码或 `keystore.properties` 提交到 Git。
4. 把 `PRIVACY.md` 发布到无需登录即可访问的 HTTPS 网页，并在各商店后台填写链接。
5. 准备 512×512 商店图标、手机和平板截图、宣传图与软件著作权/备案等目标商店要求的材料。
6. 在真机上覆盖 Android 7、主流 Android 版本和最新 Android 版本，重点测试大文献包、低存储、系统分享导入、升级安装与卸载重装。
7. 在应用商店后台如实声明：无账号、无广告、无分析 SDK；文献与阅读数据保存在设备本地；仅在用户主动连接个人 HTTPS 地址时联网。

## 构建

调试 APK：

```powershell
cd gui
npm run android:apk
```

未签名的 Release AAB：

```powershell
cd gui
npm run android:bundle
```

Release AAB 只有配置发布者自己的上传签名后才可提交商店。正式发布时每次升级都必须递增 `versionCode`，并同步更新 `versionName`、更新说明和隐私/数据安全声明。

## 暂未实现的服务器能力

账号注册、密码找回、跨设备云同步、云端备份、订阅支付、推送和远程删除均未启用。未来实现时，应以独立服务接口接入，并补充认证、加密、数据导出/删除、限流、审计、备份恢复和隐私合规设计；在服务器真正上线前，移动端不展示虚假的登录或同步成功状态。
